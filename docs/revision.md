# Willy 工程路线

## 当前原则

1. LLM 负责受限的语言理解、诊断候选和用户沟通；确定性代码负责文件、状态、权限、外部命令和科学计算。
2. 每个 run 独立存放在 `md_run/<run_id>/`。全新任务不隐式继承；`/resume` 直接沿用原工程稳定值；`/fork` 和确认后的新参数方案完整复制上下文为独立分支，父工程状态不变，重做范围内的旧准出失效。
3. 阶段只能消费已登记、已校验并获许可的上游产物。文件存在不等于阶段通过。
4. 配置修改、重跑、派生运行和停止都必须经过服务端策略和用户确认边界。
5. 前端仅消费脱敏的公开状态；命令、绝对路径、密钥、原始 prompt 和原始日志属于私有信息。

## 当前建设重点

### 运行可靠性

- 维护 schema、StepRegistry、RunStore 和 run 级事务的一致性。
- 维护独立进程组的启动、超时、停止和审计，不让文本聊天触发进程控制。
- 维持 EM、EQ、PROD 的阶段许可和 checkpoint 指纹门禁。

### Agent 治理

- 所有 Agent 仅通过本层白名单工具访问事实和动作。
- 候选方案必须通过 schema、量子输入审计和业务校验后才能等待确认。
- 自动修复只允许有限、证据门控的白名单动作；无法验证时升级为用户决策。

### 发布与验收

- 默认回归覆盖确定性契约，外部工具和浏览器通过显式目标机验收补足。
- 发布范围只承诺已经由对应证据支持的能力。
- 未关闭项集中维护在 `project_gap_analysis.md`，不以设计文档的叙述替代验收结论。

## 后续规划：启动更新提示与数据保护（未实现）

本节仅记录规划，不表示当前已支持更新检查或在线升级，也不授权构建、部署、提交或推送。第一阶段只检查更新并提示；实际升级作为独立后续事项，需另行确认范围。责任为架构与产品、前端、环境和测试；验收缺口见 `project_gap_analysis.md` 的 G-08。

### 第一阶段：只读检查与提示

- 在目标机 Willy Web 服务启动时后台检查官方仓库 `BriskWish/Automized-simulations` 的稳定 Release；这里的启动指应用启动，不新增操作系统开机服务。不自动拉取、安装、重启，也不修改源码、Python 环境或运行数据。
- 设置短超时、有限重试和检查间隔，避免阻塞 Web 启动、`/resume`、`/fork` 或正常运行；仅在 `.willy/` 下保存更新检查缓存，并提供关闭检查的入口。
- 展示当前版本、最新稳定版本、发布日期、经过清理的更新摘要及检查时间。断网、限流、无 Release 或响应异常时明确显示不可确认与缓存时效，不能误报为已是最新版本。
- 区分正式发布版本、开发版本及本地未提交修改；不能仅凭版本字符串相等就宣称源码一致。更新信息是外部不可信文本，不作为命令执行，也不直接渲染未清理的 HTML。
- 请求只用于读取官方公开发布信息，不上传配置、路径、运行信息或凭据；公开提示遵循现有脱敏边界。检查不得写入 `md_run/`、根配置或用户结构文件。

### 后续升级边界（另行确认后实施）

- 发现更新不等于允许升级。实际升级必须经用户明确确认，在无活动受管任务时进入维护状态，并阻止新启动、重试、`/resume` 和 `/fork`，避免检查后又启动任务的竞态。
- 升级前核对来源、目标版本、分支及本地修改；存在未提交修改、分支分叉或文件冲突时停止并给出人工处理说明，不自动 stash、强制 reset 或覆盖。即使采用仅快进更新，也必须单独验证数据保护条件。
- `md_run/` 当前由 `.gitignore` 忽略且未被 Git 跟踪，但这不是升级保护机制。必须拒绝目标版本将 `md_run/` 纳入跟踪或写入范围；不得清理、覆盖或删除原有 run、草稿、候选方案及其日志、配置、checkpoint、manifest 和状态文件。
- 根 `config.json` 当前被 Git 跟踪，不能按普通源码覆盖；`.env`、用户上传的 `struct/` 文件与本地环境配置同样需要保留。升级前备份必要配置和运行元数据，明确备份范围；备份不替代对整个 `md_run/` 的不改写约束。
- 不使用会删除忽略文件的 `git clean -fdx`、强制重置或镜像删除式同步。Python 兼容性以目标版本声明为准，先检查当前父解释器及依赖；不绑定 Anaconda、不硬编码 `python3`，不静默替换或重建现有虚拟环境。
- 依赖安装、前端构建、启动检查和失败回退属于维护流程，不在启动检查阶段执行。文件保留不代表旧 checkpoint 可恢复；跨版本仍须满足阶段许可、指纹与 schema 契约，不兼容时停止并说明，必要迁移须另行确认、备份且可恢复。

### 计划验收条件

1. 使用隔离替身覆盖有更新、无更新、无 Release、离线、超时、限流、异常响应、开发版本、本地修改和缓存过期；确认启动及运行控制不被检查阻塞，不安装或执行远端内容。
2. 在停用运行写入的隔离目录中检查更新前后 `md_run/`、根配置与用户文件的目录清单及哈希不变；检查缓存只能落在约定位置，公开响应不泄露私有信息。
3. 如另行实施升级，再覆盖维护锁与启动竞态、目标版本跟踪受保护路径、本地修改冲突、Python 不兼容、更新失败和回退；目标机验证既有 run 在满足原有恢复门禁时仍可续跑。

## 重构同步清单

改变步骤、配置字段、产物、工具、错误类型、状态字段、run 文件或公开能力时，必须同步：

1. 实现与最小回归测试。
2. 对应领域文档和 `status_api.md`。
3. `docs/README.md` 与 `document_registry.md` 中的导航和责任归属。
4. `testing.md` 和 `project_gap_analysis.md` 中受影响的验证规则。

## 完成定义

一个改动只有在行为、契约、测试、用户可见说明和验收边界一致时才完成。无法在当前环境证明的外部行为必须明确列为待验，不得用 mock、裸命令或旧产物替代。
