# Willy 工程路线

## 当前原则

1. LLM 负责受限的语言理解、诊断候选和用户沟通；确定性代码负责文件、状态、权限、外部命令和科学计算。
2. 每个 run 独立存放在 `md_run/<run_id>/`；新任务不继承其他 run 的产物、阶段许可或配置。
3. 阶段只能消费已登记、已校验并获许可的上游产物。文件存在不等于阶段通过。
4. 配置修改、重跑、派生运行和停止都必须经过服务端策略和用户确认边界。
5. 前端仅消费脱敏的公开状态；命令、绝对路径、密钥、原始 prompt 和原始日志属于私有信息。

## 当前建设重点

### 运行可靠性

- 维护 schema、StepRegistry、RunStore 和 run 级事务的一致性。
- 维护独立进程组的启动、超时、停止和审计，不让文本聊天触发进程控制。
- 维持 EM、EQ、PROD 的阶段许可和 checkpoint 指纹门禁。

### Agent 治理

- 所有 Agent 仅通过本层白名单工具访问事实和动作。
- 候选方案必须通过 schema、量子输入审计和业务校验后才能等待确认。
- 自动修复只允许有限、证据门控的白名单动作；无法验证时升级为用户决策。

### 发布与验收

- 默认回归覆盖确定性契约，外部工具和浏览器通过显式目标机验收补足。
- 发布范围只承诺已经由对应证据支持的能力。
- 未关闭项集中维护在 `project_gap_analysis.md`，不以设计文档的叙述替代验收结论。

## 重构同步清单

改变步骤、配置字段、产物、工具、错误类型、状态字段、run 文件或公开能力时，必须同步：

1. 实现与最小回归测试。
2. 对应领域文档和 `status_api.md`。
3. `docs/README.md` 与 `document_registry.md` 中的导航和责任归属。
4. `testing.md` 和 `project_gap_analysis.md` 中受影响的验证规则。

## 完成定义

一个改动只有在行为、契约、测试、用户可见说明和验收边界一致时才完成。无法在当前环境证明的外部行为必须明确列为待验，不得用 mock、裸命令或旧产物替代。
